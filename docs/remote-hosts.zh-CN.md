# 远程主机（SSH）使用说明

在同一个窗口里同时使用本机项目和远程服务器上的项目。远程项目在侧边栏的项目名后面显示一个淡蓝色地球 🌐；主机离线时地球变灰。

远程项目的 Agent、会话、文件、终端、git 都**运行在远程服务器上**：关闭窗口、合上电脑或网络中断都不会打断远程任务，重新连接后继续查看。

## 前提

| 要求 | 说明 |
|---|---|
| 免密 SSH | 在终端里 `ssh <目标>` 能直接登录，不弹密码（密钥或 ssh-agent）。主机指纹需要已被接受。 |
| 远程 Node.js | 22.19 或更新，在 `PATH`、`/usr/local/bin` 或 `/usr/bin` 中。 |
| 远程系统 | Linux x64 / arm64，或 macOS。 |
| 磁盘 | 每个版本约 160 MB，安装在远程 `~/.pi-remote/`，只保留当前版本。 |

不需要 root，不需要远程能访问外网（服务端由本机上传）。

## 添加主机和项目

1. 点侧边栏「项目」右侧的 **+**。
2. 选择 **管理 SSH 主机…**（第一次是「添加 SSH 主机…」）。
3. 在「SSH 目标」里填 `~/.ssh/config` 中的别名，或 `user@host`、`-p 2222 user@host`，点 **连接**。
   首次连接会自动：检查远程环境 → 上传服务端 → 启动 → 建立隧道 → 登录，通常十几秒。
4. 连接成功后会弹出远程目录浏览器，选择项目文件夹即可。

之后点 **+** 时，菜单里会直接列出已添加的主机。

## 日常使用

- **会话**：远程项目里新建、继续会话和本地完全一样。远程 CLI 里的已有会话也会出现在侧边栏。
- **设置**：设置窗口标题旁的「配置范围」决定模型、技能、MCP、插件等配置读写哪台机器，默认跟随当前项目。远程项目使用远程机器自己的 `~/.pi/agent` 配置。
- **终端 / 文件 / git**：都在远程执行。「在 Finder 中显示」「用默认程序打开」等本机操作在远程项目里会隐藏。
- **离线**：主机断开时项目仍在列表里，地球变灰，顶部出现横幅，可「重新连接」或「诊断」。网络恢复后会在几秒内自动重连（连续失败时间隔逐渐拉长，最长 60 秒），对话区自动刷新。

## 远程上的文件

```
~/.pi-remote/
├── versions/<版本>/     服务端程序
├── secret              访问密码（0600，每台主机随机生成）
├── state.json          运行中的端口、进程号
└── logs/server.log     服务日志
```

服务只监听远程的 `127.0.0.1`，并始终要求密码；本机通过 SSH 读取密码，只保存在内存中。

在「管理 SSH 主机」里移除主机只会删除本机的记录，远程服务继续运行。需要停止时：

```bash
ssh <目标> 'kill $(node -e "console.log(require(process.env.HOME+\"/.pi-remote/state.json\").pid)")'
```

## 升级

桌面端升级后，下次连接会自动上传新版本。如果远程旧版本上还有任务在运行，不会被强制替换，横幅会提示，可以等任务结束后重新连接，或点「立即升级」（会中断这些任务）。

## 已知限制

- 只支持免交互的 SSH 认证；需要输入密码或二次验证的主机暂不支持。
- 远程会话的**全文搜索**和**定时任务**列表目前只显示本机的（远程定时任务仍在远程正常运行）。
- 在远程项目里用 OAuth 登录模型服务商时，浏览器回调会落到本机，需要使用对话框里的「粘贴回调地址 / 代码」方式完成。
- 两台机器上完全相同的路径会显示为两个项目；它们的折叠、归档状态共用。
- 同一个远程会话被远程 CLI（`pi --resume`）同时写入时，会话会分叉（pi 本身没有文件锁）。

## 排查

- 「诊断」会逐项检查本机 ssh、服务端包、远程环境，并附上远程服务日志末尾。
- 本机日志：桌面端「设置 › 通用 › 打开日志」中的 `server.log`。
- 远程日志：`~/.pi-remote/logs/server.log`。
